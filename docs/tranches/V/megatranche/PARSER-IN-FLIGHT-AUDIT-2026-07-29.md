## 1. Outcome

The parser program must not call the current W3 CSS public witness “CSS
coverage.” It is a **CSS-shaped P2 nested-region control**. Its four cases prove
only comments, quotes, balanced regions, one grammar-declared continuation
policy, rollback, and full consumption through the generic event vertical.
It proves zero normative CSS token kinds, preprocessing, stylesheet recovery,
selector grammar, declaration grammar, property grammar, typed value grammar,
CSSOM, cascade, or computed-value behavior.

The minimum honest architecture is layered, but every parser layer consumes
the source directly through parse-that combinators:

```text
source bytes
  -> source-direct CSS Syntax combinators with lossless spans/recovery
  -> component values and generic rule/declaration algorithms
  -> module-profiled typed values and descriptors
  -> value.js extension profile
  -> context/cascade/computed behavior in named consumers
```

“Full CSS” therefore means a standards-bounded syntax floor plus an explicit
module/version/profile matrix. It does not mean one monolithic grammar that
pretends to encode every property, selector, cascade rule, and browser semantic
algorithm.

SK-V26 W3 should close without widening the active implementation. Full CSS
then requires the smallest consumer-proved parse-that repair before Value owns
the source-direct CSS vertical:

1. deterministic multi-source/module linking or source bundling;
2. CSS preprocessing and lossless span/recovery identities without a token
   tape as parser input;
3. structured diagnostic spans and recovery events;
4. a Value-owned source-direct CSS Syntax combinator layer;
5. module-profiled typed consumers;
6. equivalent-plane profiling only after correctness.

## 3. What “full CSS” binds

### 3.1 Normative syntax floor

The first conformance surface is the algorithms in CSS Syntax Level 3:

- input preprocessing, including replacement of null, surrogate, and
  non-scalar code points and CR/FF newline normalization;
- the complete tokenization state machine;
- escaped code points, ident-like, numeric, URL, string, comment, delimiter,
  CDC/CDO, punctuation, and block token classes;
- representation-preserving reparsing for `<urange>` where a module grammar
  enables it; `<urange>` is not a normative tokenizer token kind;
- component-value construction with function/simple-block nesting;
- generic lists of rules, at-rules, qualified rules, declarations, and
  declaration lists;
- parse-error continuation and EOF behavior;
- lossless source spans under one declared raw-preservation policy.

CSS-wide whitespace cannot be implemented by the W3 instance-wide
`trivia_regex` plus `?w`. Comments, escapes, bad strings/URLs, EOF closure,
unmatched closers, and recovery are source-grammar semantics, not globally
discardable trivia or an excuse for a competing scanner stage.

### 3.2 Module profiles

The current CSS Snapshot is the catalog authority; each imported grammar or
algorithm still records the exact module version and stability. The first
value.js consumer profile is intentionally narrower than “all CSS properties”:

| Profile | Required first surface | Explicitly outside its first close |
|---|---|---|
| Syntax | full preprocessing, source-direct component values, generic rules/declarations/recovery, and lossless spans | CSSOM and cascade |
| Values | dimensions, percentages, ratios, functions, math, substitution-bearing component values | resolution without context |
| Color | Color 4 plus selected Color 5 functions with exact context policy | pretending project spaces are CSS-native |
| Images/Gradients | gradient/image value syntax consumed by current Gradient routes | image fetching/rendering |
| Animations | keyframes, timing functions, animation values | animation engine scheduling |
| Scroll-driven animations | timelines, ranges, named timeline values | layout/scroll resolution |
| Conditional/Nesting/Scope | generic preservation plus profiled preludes | selector matching and cascade |
| Properties & Values API | `@property` descriptor syntax and typed-value boundary | browser registration side effects |
| Mixins/Custom functions | exact selected draft grammar with a version pin | browser-wide interoperability claims |

Future module rows are additive profiles. They do not widen the syntax tokenizer
or create a second parser runtime.

### 3.3 value.js additions

Current Webref includes `ictcp()`, `jzazbz()`, and `jzczhz()` as standard CSS
Color HDR functions. The presently verified Value additions are only `hsv()`
and `kelvin()`, pending denominator freeze. They belong to a named `value-js`
extension profile
with:

- explicit prefix/name ownership;
- exact accepted grammar and serialization;
- collision policy if a future CSS module claims a name;
- conversion/gamut/context requirements;
- no inclusion in CSS conformance percentages.

The same law applies to any project-only easing, timeline, palette, or transform
surface. Extensions may reuse the syntax/event substrate; they may not alter
normative CSS tokenization.

### 4.2 Reproduced root defects

The audit invoked current source directly:

```text
parseCssColor("rgb()")   -> throws reading undefined.replace
parseCssColor("rgba()")  -> throws reading undefined.replace
parseCssColor("hsl()")   -> throws reading undefined.replace
parseCssColor("color()") -> throws reading undefined.replace
```

The cause is the non-null assertion on `slash[0]` in
`src/css/grammar.ts::parseFunctionalColor`. A failure-explicit API may not throw
for ordinary invalid input.

Two stylesheet probes expose the deeper architectural problem:

```css
a { color: red; broken; background: blue }
a { --x: { a: b }; color: red }
```

The first aborts the entire result at `broken` instead of applying CSS
declaration recovery. The second silently drops the custom-property declaration
and reclassifies `--x:` as a nested style. Both arise from handwritten
top-level splitting that guesses structural meaning before normative
token/component-value construction.

Diagnostics carry a useful target shape (`code`, `start`, `end`, `expected`,
`actual`) but most failures currently report a whole local substring or whole
input. The parse-that Rust `Failure` carrier exposes only the furthest cursor.
The generated event boundary must therefore evolve after W3 to preserve
structured spans; value.js must not manufacture precision it did not receive.

### 4.3 Current handwritten structure

The current parser contains at least three overlapping scanners:

- `splitTopLevel`;
- `splitValueTokens`;
- the block/declaration scans in `stylesheet.ts`.

They do not share one escape/comment/bad-token/recovery state machine.
`src/css/grammar.ts` is 483 lines and `src/css/stylesheet.ts` is 899 lines; line
count is not the defect, but the repeated structural scans are. A clean break
should replace them with one CSS Syntax token-event authority, then keep small
typed consumers colocated by module.

Do not preserve these helpers behind aliases, shims, compatibility fallbacks,
or a generated-parser-to-handwritten-parser escape. The old paths remain only
until their replacement matrix and crater are green, then are deleted in the
same cut.

### 5.1 Existing value.js prototype

The existing `docs/tranches/V/megatranche/prototypes/css-parser` suite passed:

It is a bounded CSS Color/P4 experiment. It is not a full CSS parser. Its prior

|---|---:|---:|---|

| cand-O rejected AST | 283 ns | 180 ns | slower directional row |
| cand-F valid | 466 ns | 583 ns | directional |
| cand-F R1 reject | 302 ns | 34,550 ns with throw/catch | incomparable error-cost warning |

The clean-room audit added a deterministic reference syntax prototype and
paired/profile receipts in an isolated worktree, committed at
`dea7a93c92823a05e2ad99f9f82b82edb8d6b822`. Focused TypeScript and 21/21
reference tests pass. Five WPT-derived projections are pinned; this is focused
prototype evidence, not broad conformance.

The P4 color-only paired adjudication rejects every candidate for promotion:
cand-O node is about 10% faster on accepted input but about 28% slower on
ordinary rejection; cand-O drop-in has no accepted-input win and the same
rejection regression; cand-F is about 13% faster on the one accepted family but
about 6% slower on rejection and has no second representative win. The large R1
ratio is incomparable because published 4.0.0 throws while candidates reject.

The readable syntax oracle processed the 1 MiB families at roughly 9–13 MiB/s
for tokenization and 8–10 MiB/s for generic stylesheet construction. CPU
profiling identifies tokenizer helpers, allocation-rich component construction,
token dispatch, preprocessing, and GC; the oracle's object layout is therefore
rejected as implied production architecture while its algorithms remain a
differential reference.

Neither result can certify SK-V26, because the value prototype uses TypeScript
parse-that 1.0 while SK-V26 uses Rust parse-that 0.5/ABI-3. Exact raw samples,
simultaneous intervals, profiles, hashes, and reproduction commands are in
`PARSER-RESUME-HANDOFF-2026-07-29.md`.

### 5.3 W2 negative evidence

The SK-V26 W2 scalar classifier profile is a rigorous rejection, not a buried
partial success: long scalars improved roughly 31–38%, while whitespace and
punctuation families regressed roughly 17–24%. The design disposition is:

- no always-on classifier;
- no NEON promotion from microkernel evidence;
- preserve the scalar oracle;
- profile eligibility and selection once per parser;
- require end-to-end P2 movement on representative families.

### 5.4 Certifying benchmark planes

The active benchmark constitution is correct and remains binding. Its
historical `P<n>` names are semantic planes, not the parser addendum's wave
numbers:

- benchmark-plane P1 validation;
- benchmark-plane P2 normalized full-consumption token/event checksum;
- benchmark-plane P3 lossless representation;
- benchmark-plane P4 decoded DOM;
- benchmark-plane P6 typed values;
- benchmark-plane P7 transform/serialization.

`cssparser` is a candidate benchmark-plane P2 baseline, not a typed stylesheet
baseline. Lightning CSS is a candidate benchmark-plane P7 baseline only at
equal typed coverage.
Browser acceptance, PostCSS parsing, and WPT expectations are correctness
oracles, not automatically equivalent performance competitors.

Every promotion run requires semantic/error equivalence, deterministic content
hashes, A/A calibration, paired interleaving, raw samples, simultaneous
confidence intervals, environment/flags, allocation/retention/checksum policy,
and profiles. A microkernel win is banked unless it moves an end-to-end
consumer.

The audit used the in-app Browser against current browser support and the W3C
specification pages. The browser accepted representative modern forms such as
`color-mix`, `light-dark`, `scroll()`, and `view()`, while project-only color
functions remained unsupported. Browser behavior is a useful deployed
compatibility oracle, not the normative source.

Counts are inventory only. Each imported case must state:

recovery progress, bounded resource behavior, and zero ordinary-invalid-input
throws.

1. Finish and freeze the active W3 generic event vertical; do not widen it to

   production architecture.
9. No SOTA claim is available until an equivalent full-consumption plane moves
   end to end under the benchmark constitution.

    `AUDITED -> SPECIFIED -> IMPLEMENTED -> VERIFIED`; this audit advances no
