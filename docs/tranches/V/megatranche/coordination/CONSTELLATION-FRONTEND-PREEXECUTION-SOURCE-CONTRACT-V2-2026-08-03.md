## 2. Noncircular inner and outer seals

The exact 29-file inner payload is frozen first. `INNER-CHECKSUMS.sha256`
hashes all 29 payload files and never itself. `INNER-SEAL.json` binds that
checksum, the pre-seal tree, counts, bytes, contract pins, and write order.
Neither file claims a hash fixed point.

Only after the inner packet is frozen may the validator run. Its raw process
receipt records runtime, command, cwd, allowlisted environment, time, exit,

inner tree before/after, writes, and external reads.

`OUTER-CHECKSUMS.sha256` then hashes the complete inner packet and validator
receipt, excluding itself and `OUTER-SEAL.json`. The outer seal binds that
checksum and the pre-seal tree. A later external terminal tuple—not a

## 4. Typed schemas and exact spans

`RECORD-SCHEMAS.json` uses JSON Schema 2020-12 for every JSON member. Unknown
properties, untyped arrays, missing cardinalities, unresolved references,

authorized schema hash prevents the writer from weakening the grammar.

Every source claim uses a byte span over the raw snapshot. A span binds member
path, inclusive start, exclusive end, byte length, slice hash, syntax-node
kind, and semantic role. Lines are informational only. The validator
recomputes the slice and rejects an unrelated span cited merely to satisfy a
field.
