# Constellation megatranche development drive

**Date:** 2026-07-29  
**State:** ACTIVE DEVELOPMENT; no product-source execution  
**Root:** `value.js` Tranche V megatranche  
**Subjects:** `value.js`, `keyframes.js`, `fourier-analysis`, `parse-that`  
**Coordination peers:** `glass-ui`, `bbnf-lang`, sci/Atlas  
**Outer consumer census:** `bbnf-buddy`, `latex-paper`, `muster`, `sci-report`,
`slides`, `slides-k`, `speedtest`, `words`

This document supersedes every Value-only reading of the megatranche. It
reformulates the original in-flight audit prompt into a long-horizon,
multi-repository development program. Each subject repository receives its own
session, goal, convergence loop, and precepts-complete wave packet. The root
session coordinates ownership, cross-repository edges, and final formation.

## 1. Goal criterion

The program succeeds when the four subject repositories form one coherent
megatranche: each library has a small, intelligible, consumer-proven public
surface; each frontend has a distinctive, glass-native, browser-verified
product structure; the shared parser and CRUD/provenance contracts have one
owner apiece; and every carried prompt, chronic, component, graph cluster, and
consumer break receives a terminal `KEEP`, `FOLD`, `MOVE`, `SPLIT`, or
`PRUNE` disposition with its owning wave action stated separately.

## 2. Completion criterion

Formation completes only when:

1. each subject repo has one canonical tranche authority with parent goal,
   current progress, open/terminal close contract and a fully populated
   executable specification for every broad or parallel wave. A repository
   may use standalone `waves/W<N>.md` files or one immutable packet with
   self-contained wave sections; digest-only table rows and duplicated
   authorities are inadmissible;
2. every tranche, wave, and agent unit states a goal criterion and an
   evidence-bearing completion criterion;
3. every live defect has a born-RED probe, every visual claim has named π and
   DELTA cells, and every performance claim has saved benchmark/profile
   artefacts;
4. every component has its own workflow and every library/component/API DAG
   cluster has survived two independent hostile readings plus a Sol xhigh
   adjudication;
5. at least three complete
   research→synthesis→prototype→critique→agglomeration passes have run per
   subject, followed by two consecutive fresh adversarial passes with no new
   defect family;
6. the cross-repo ownership matrix, dependency order, version/pin migration,
   and conflict protocol agree in every repo packet;
7. no open gap is hidden under “routine,” “later,” “follow-up,” compatibility
   code, or a consumer-less substrate.

Passing document checks without satisfying the goal closes nothing.

## 3. Mode boundary

This is tranche development.

- Product-source implementation does not land from this program.
- Greenfield prototypes are required where they decide architecture,
  performance, browser behavior, or API feasibility. They live in isolated
  task worktrees or named prototype roots, never in the product path that a
  later implementation wave will modify.
- A prototype is evidence, not authority. Its surviving mechanism must be
  re-authored into the owning repo's wave specification.
- Temporary cross-repo consumption uses built package artefacts. Workspace
  links resolve published `dist` in development and production; publisher
  `build:watch` keeps it current. No raw-source alias, `development` export
  condition, copied producer CSS, or widened sibling-source path is allowed.
- No session commits or edits another repo. Cross-repo requests travel through
  the root coordination ledger in batches.

## 4. Model and iteration law

Historical receipts retain their real model names. New work uses:

| role | model | duty |
|---|---|---|
| portfolio, synthesis, design, critique adjudication, agglomeration | GPT Sol xhigh | cognitively complex judgment and orchestration |
| mechanical archaeology, prototype implementation, benchmark fanout | GPT Luna xhigh | bounded extraction and implementation |
| final family adjudication | fresh GPT Sol xhigh | attempt to disprove the surviving routes and write one choosy result |

Every design route uses the frontend-design skill. Sol and Luna develop
independent designs; the final Sol sees both only after they are complete.
Frontend audits use the in-app Browser for every public route, component
state, and owned interaction. Browser evidence separates desktop, mobile,
short landscape, keyboard, reduced motion, forced colors, RTL, loading,
empty, error, offline, and authenticated states.

Each pass is its own durable workflow:

1. **Research:** independent repo, history, session, standards, consumer, and
   performance lanes; favored routes withheld.
2. **Synthesis:** one specification per still-incompatible family.
3. **Prototype:** running greenfield mechanisms or an explicit spec-only
   status with the missing primitive named.
4. **Critique:** falsification against correctness, allocation, deopt,
   accessibility, visual hierarchy, consumer truth, and legacy-path failure
   modes.
5. **Agglomeration:** Sol xhigh advances, banks, blocks, or retires every
   family and opens the next pass from the resulting registry.

Keep incompatible families alive until evidence retires them. Convergence
requires three complete passes, zero enumerated open gaps, two fresh clean
adversarial passes, and a fully authored wave set.

## 5. Shared architecture law

All four subjects obey these conditions:

1. KISS and deletion dominate. A smaller complete mechanism beats a larger
   configurable one.
2. Clean breaks only: no aliases, shims, dual exports, compatibility layers,
   masking fallbacks, stale barrels, or legacy directories.
3. Substrate and consumer land in the same eventual implementation wave.
4. Consumer count is evidence, never a verdict. Semantics, change coupling,
   performance, and product need decide.
5. Use Goldilocks grain. Split at independently nameable invariants and change
   boundaries; flatten ceremonial one-file directories and forwarding shells.
6. Inside module `x/`, child filenames do not repeat `x`: `easing/option.ts`,
   not `easing/easing-option.ts`.
7. Tests live outside `src` in an isomorphic test tree unless the runner
   demonstrably requires colocation.
8. Public surfaces are fail-explicit on library-owned contract violations.
   Browser/API degradation remains a separately tested product behavior.
9. No general `utils`, `helpers`, `common`, `manager`, or `service` bucket
   survives without one coherent semantic owner.
10. Glass components are preferred aggressively where their semantics fit.
    Bespoke components survive only when the semantic or visual loss from
    adoption is measured and accepted.

## 6. Graph program

Each subject produces typed graphs for source, tests, frontend components,
styles/assets, routes, state, dependency injection, API operations, workers,
package exports, and cross-repo consumers. Python and Rust surfaces enter where
present.

Dynamic graph clusters determine batch size. Each cluster receives:

1. one independent Sol xhigh critic assuming the graph is wrong;
2. a second independent Sol xhigh critic using a different decomposition;
3. a fresh Sol xhigh adjudicator that attempts to disprove both and records
   terminal KEEP, FOLD, MOVE, SPLIT, or PRUNE dispositions.

Graph tools are evidence only when alias resolution, Vue render edges, CSS
imports, state/DI/API ownership, package exports, and language-specific edges
are represented. Count-only graphs cannot authorize a move or deletion.

## 7. Parser and CSS program

The active parser session
`019fae36-1241-7d33-9c14-58d86be7fae3` is the parser development owner.

- `parse-that` owns reusable runtime, combinators, spans, recovery,
  diagnostics, recursion behavior, and performance.
- Value owns the sole CSS grammar, CSS consumer, public CSS behavior, and UI.
- Keyframes consumes the Value CSS surface and supplies authored animation,
  keyframe, timeline, easing, value, and transform workloads.
- BBNF is a research/ABI peer. It supplies one boundary receipt after its W3
  freeze and creates no competing CSS parser or registry.
- There is no tokenizer, token array, token-event tape, scanner facade, or
  separate lexing stage in the production architecture.
- Source-direct fused terminal primitives may use ASCII classification,
  vectorized comparisons, typed arrays, or other low-level techniques inside
  combinator semantics. They may not materialize a scanner-shaped intermediate
  representation or create a second parser path.

The parser portfolio must assay run-scoped state, exact sequencing, unordered
composition, source projection/spans, bounded or stack-safe recursion,
diagnostics, recovery, memo policy, functor allocation, string/number
materialization, inline-cache stability, hidden classes, escape analysis,
deopts, GC pressure, and cold versus hot dispatch.

Performance admission is ≥10× the frozen parse-that baseline at the lower
bound of the benchmark confidence interval on equal semantic work. The
baseline and candidate must return equivalent values, spans, diagnostics, and
failure behavior. Any benchmark that omits work, warms only one side, or
compares a recognizer with a value-producing parser is invalid. Failure to
reach 10× leaves convergence open; it does not invite a weaker narrative
gate.

Full CSS admission requires executable, source-direct combinator coverage for
the frozen CSS denominator, including CSS Syntax, selectors, at-rules, Value
Definition Syntax, Webref property/type/function grammars, recovery, spans,
browser/WPT differentials, and separately named Value extensions.

## 9. Glass and design law

Golden Glass is optical housing for the subject's instruments. Breath of Life
is the state legibility floor: rest, hover, grab, select, commit, loading,
error, and recovery must feel causally related. Movement of Momentum assigns
one driver to each motion system and preserves velocity, direction, and
settling logic across state changes.

Each route names:

- its audience and single job;
- one protagonist or instrument;
- one subject-specific visual signature;
- the semantic stage, inspector, and action regions it actually needs;
- the controls or decoration it can delete.

Glass gaps are batched at the root. A packet is sent only after a substantial
cluster has been adjudicated and contains exact consumer evidence, the general
producer mechanism, degraded posture, and acceptance cells. No ad hoc local
producer emulation is permitted.

## 10. Session durability and admission

Every repository session must establish a long-horizon goal and preserve:

- exact checkout, branch, head, dirty-state, and immutable-baseline receipts;
- a session/tranche/commit archaeology ledger;
- an approach-family registry and pass ledger;
- component workflow coverage and hash-banked outputs;
- DAG cluster inputs, adjudications, and terminal dispositions;
- prototype source, benchmark/profile artefacts, browser captures, and
  falsification results;
- the canonical tranche plan and wave specifications;
- one exact resume cursor and one findings/handoff document.

A repository session is admitted into the constellation plan only when its
wave packet satisfies
`docs/precepts/instructions/tranche/WAVE_SPEC.md` in full. It must resolve the
repo's current active or next unused tranche letter from evidence; it may not
invent, reuse, or silently supersede a letter. Admission does not authorize
implementation.

## 11. Root coordination

The root session:

1. owns the cross-repo DAG, dependency order, session registry, and terminal
   prompt/chronic ledger;
2. resumes existing active sessions before creating duplicates;
3. sends each session one bounded delta at safe boundaries;
4. never repeats an acknowledged Glass batch;
5. freezes shared public-surface decisions only after every affected subject
   has returned an exact consumer disposition;
6. rejects any repo packet that calls audit coverage, prototype success, or
   source-only tests “wave complete”;
7. agglomerates repo-grouped waves into a multidimensional dependency graph
   without turning cross-repo edges into a single omnibus writer wave.

The final handoff names every session ID, repo head, admitted wave packet,
blocked family, exact next action, and cross-repo release condition. No
progress is allowed to depend on the survival of a single chat context.
