# Wave routing and π classes

Every wave row carries one compact routing/π value before its Exclusions cell;
the table therefore has eight cells total. Nonvisual rows use exactly
`R0 · N/A(no-visual-claim)`. Visual rows use exactly
`R1`–`R5 · <named-evidence>-π/DELTA`, where the evidence token is a stable
alphanumeric/dot/slash/hyphen identifier and the row's gate owns the expanded
artifact contract. Bare routing codes and prose-filled routing cells fail.
The code is a compact contract, not a waiver. At formation, two fresh hostile Sol critics and
one fresh Sol adjudicator challenge the row. During later execution, Sol owns
design, novelty, skepticism and adjudication; Luna may run only the mechanical
censuses, fixtures and captures enumerated by the accepted row. Every seat
reports `model_served`; compact spot probes replace provider-transcript
forensics.

| Code | Applies to | π / DELTA obligation |
|---|---|---|
| `R0` | Nonvisual library, API, graph, structure, coordination or release work. | `π=N/A` must name why no rendered claim exists. DELTA is the row's exact type, byte, graph, package, API or benchmark witness. |
| `R1` | Rendered primitive, material, color plate or bounded component work. | Same semantic state before/after at compact and desktop, light/dark, PRM and forced colors; computed geometry/style plus accessibility tree; no representative-screen substitution. |
| `R2` | Whole route, pane, shell or scene composition. | Same route/state at 320, 390, 430, tablet and 1440 widths; light/dark, PRM, forced colors, keyboard and touch; loading/empty/error/full where applicable. |
| `R3` | Direct manipulation, gesture, curve or choreography. | `R2` plus PL-10 traces for position, velocity, acceleration/impulse, 1→2→1 pointer transitions, cancel/lost-capture, interruption, settle and zero hidden/idle work. Thresholds come from rendered measurement, never prose. |
| `R4` | Shared visual/input probe, every-page audit or cross-app design gate. | C00P isolated-profile evidence: safe-area and software-keyboard oracle, authenticated-admin recipe, multitouch synthesis, DPR-aware geometry, raw capture hashes and explicit unavailable-device REDs. Existing valid before captures are reused. |
| `R5` | Named physical-device closure. | `R4` on physical iPhone/Safari, Android/Chrome and Mac browsers, with assistive technology, refresh/power/thermal facts and raw trace hashes. Emulator-only evidence cannot green it. |

PL-11 labels the opening state of every row:

- `BORN-RED`: the defect is live and a stated probe fails now;
- `BORN-ABSENT`: the required artifact or implementation does not exist, and
  absence—not a fabricated failing test—is the opening witness;
- `RULING`: the owner has already decided the outcome; the wave proves and
  executes it without reopening worth;
- `AUDIT`: the wave opens from a precommitted falsification suite and may never
  invent a synthetic implementation failure.

The Born-RED cell must use one of those labels after the union rewrite. A visual
row may not use `R0`; a nonvisual row may use a visual class only when its gate
names the rendered artifact it owns.
