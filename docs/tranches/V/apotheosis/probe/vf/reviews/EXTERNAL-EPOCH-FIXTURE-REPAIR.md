# External-Epoch Fixture Repair

## Disposition

The external-epoch fixture defect is repaired at formation scope. Value and
Keyframes fixtures now construct five isolated Git roots, observe every root
through the resolver's exported Git-identity implementation, commit a relocated
authority before the relevant baseline epoch, run the real resolver twice and
bind the exact resolver-produced receipt. No production source, active
BBNF/parse-that artifact or quarantined `r1-opus-refuted` content was read or
changed.

This report records formation evidence only. It does not execute V29T, K22T,
M00, M10T or K23 as product waves.

## Landed repair

- `tools/consumer-bounds-authority.mjs` owns the canonical three-field
  `{path,file_sha256,manifest_hash}` binding and the exact five-root, scope and
  quarantine law.
- `tools/resolve-consumer-universe.mjs` exports `resolveGitIdentity()`; resolver
  output and receipt validation now prove the complete input root/edge,
  disposition, evidence, count, blocker and observed-epoch projection.
- `consumer-universe-receipt.schema.json`, `return.schema.json` and
  `deletion-judgment.schema.json` use the authority object only. No scalar alias
  or dual representation remains.
- `tools/consumer-universe-fixture.mjs` builds five sibling local Git roots,
  commits the relocated authority in the primary root, uses the real resolver
  twice, compares exact roots/edges modulo timestamps and dependent hashes, and
  proves every root and observation remains beneath the temporary fixture.
- Value resolution/transpose and Keyframes K22T/M00/M10T/K23 fixtures consume
  that shared construction. The Value transpose declares the exact
  `value -> parse-that` runtime edge across every generated grammar TypeScript
  occurrence; K23 declares its exact `keyframes -> value` manifest edge.
- Every deletion casualty scan dispositions all five included roots. Physical
  truth remains joined only to the repository actually changed.
- `tools/validate-return.mjs` maps an alternate logical authority through
  exactly one pinned clean worktree only in historical-certificate or immutable
  modes, requires one tracked regular non-symlink entry, preserves the logical
  binding in projections, reuses the gate worktree cache and retains historical
  mode for recursive deletion-return validation.
- `tools/return-validation-mode.mjs` supplies the one recursive-mode selector
  used by the universal validator and the recursive child-process control.

Branch or HEAD uniqueness across independent repositories is explicitly not a
law. Several legitimate roots may use `main`, `master` or even share an object
ID. The resolver instead compares each declared root's full
branch/HEAD/dirty/origins/worktrees vector with that root's own observation
before and after the frozen scan.
