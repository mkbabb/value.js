## Binding keyframes state and history law

M01 owns one `AppState`, total reducer/action boundary and runtime-handle
registry. Every writer is enumerated. Committed state contains only settled,
typed scene truth; pointer identities, DOM/Animation objects, playback/current
time/iteration, focus, Home selection, open panels and gesture previews remain
runtime-only. Home is the route alone and has no `s` payload.

M02 binds the codec to JCS, unpadded base64url and the exact limits in
[`../STATE-ROUTING.md`](../STATE-ROUTING.md): URL 6144 UTF-16 units, `s` 6000
ASCII characters, decoded JSON 4500 UTF-8 bytes, depth 12, 512 nodes, 64 keys
per object, 128 array members, 64 code units per key and 1024 per string.
Unknown, duplicate, future, noncanonical and nonfinite input refuses visibly;
it is never silently repaired.

A continuous interaction is one transaction:

1. `BEGIN(A)` captures committed state A and creates runtime-only preview;
2. repeated updates render preview without changing `AppState`, URL or
   history;
3. `COMMIT(B)` atomically dispatches once and pushes one entry iff `B != A`;
4. cancel, lost capture, reset or route leave discards preview with no write;
5. pop/hash navigation first cancels preview, then atomically replaces
   committed state without echo;
6. sharing refuses unsettled preview or commits through the same semantic
   action before encoding.

The exact seven route schemas, quaternion canonicalization and shareable versus
transient fields live in [`../STATE-ROUTING.md`](../STATE-ROUTING.md). No
second codec or history policy may exist in a feature.
