# Formation Clean-Pass Protocol

## Purpose

This protocol closes formation only. It cannot satisfy the future C08/C09
execution-close, publish a package, or turn a born-RED implementation gate
green. A finding in either pass changes the frozen corpus, invalidates every
report against the earlier epoch, and resets the count to pass 1.

## Frozen input

Run `node tools/corpus-epoch.mjs` only after every formation authority,
validator, schema, wave row and amendment is final. Both passes receive the
same exact epoch SHA-256. The excluded clean reports and final manifest may not
alter that epoch. The quarantined `r1-opus-refuted/` directory is forbidden:
neither a critic nor a tool may traverse or read it.
If that basename is encountered inside the bounded corpus, enumeration fails
before path metadata or descendants are opened; silently omitting an ingested
quarantine cannot yield a complete corpus.
The epoch also hashes the two exact external seed letters; their links are
regular-file, no-symlink and SHA-256 checked. The coordinator and host
filesystem are the explicit trust boundary: opening and closing actor epoch
receipts detect drift, but this formation proof does not claim protection from
a malicious kernel that swaps and restores bytes between those receipts.

2. `critic_b`, independently, with the same hostile directive and no sibling

3. `adjudicator`, with the literal directive `ADJUDICATE-FORMATION` and the

## Report contract

Reports use the exact paths
`reviews/FORMATION-CLEAN-PASS-{1,2}-{A,B,ADJ}.md` and contain:

- the matching `FORMATION-CLEAN-PASS-<pass>-<role>` signature;
- the exact corpus epoch;
- nonempty `Evidence reviewed:` and `Commands executed:` sections;
- the disposition of every required coverage domain;
- the exact terminal section `## Findings` followed by `None.`;
- `Verdict: **CLEAN**` only when all four result vectors are empty;
- exactly one final one-line machine attestation.

The actor's final answer contains no preface or coda:

```text
BEGIN VNEXT-CLEAN-REPORT
<exact report bytes, including the final newline>
END VNEXT-CLEAN-REPORT
```
The final message contains exactly one outer BEGIN/END pair; persisted report
bytes contain neither marker. Nested, repeated, or body-local envelope markers
are RED.
Reports contain no fenced Markdown. Their sole findings heading, `None.`, CLEAN
verdict and canonical attestation are the exact terminal tail; no other
`Verdict:` line is legal. The final
envelope is byte-equal to `task_complete.last_agent_message`. Each report is at
most 12,000 UTF-8 bytes, so an adjudicator's fixed 20,000-token read cannot
silently truncate it; the validator additionally compares each read receipt
byte-for-byte with the persisted critic report.

The `Commands executed:` body is an exact ordered projection of every logical
launch command in the actor transcript, including the opening and closing
`corpus-epoch.mjs` boundaries. Each row is exactly `- <single-line command>`.
An asynchronous launch appears once at its launch command; its owned poll cells
appear zero times. Every row terminates in one LF, and exactly one blank line
separates the final row from the byte-exact `## Findings` heading. Omission,
insertion, reordering, duplication, indentation, or padding is RED.
ASCII or Unicode horizontal padding cannot shadow a second evidence, command,
or Findings heading; each reserved heading has one byte-exact occurrence.
The case-insensitive ASCII token `findings` is reserved exactly once for that
canonical heading; source evidence must choose another line if necessary.
Reports and commentary use LF only and contain no CR, NEL, Unicode line or
paragraph separator, or Unicode default-ignorable code point. These byte laws
exclude Setext/inline heading aliases, zero-width/BOM/bidi shadows, and fused
logical lines without embedding a Markdown parser in the gate.
The report reserves its only two `#` bytes for the exact `## Findings` line;
commentary contains no `#`. Setext underline-only lines are forbidden. Outside
the one canonical machine-attestation comment, report prose contains no angle
bracket and commentary contains none. This closed safe form rejects ATX,
Setext, raw-HTML, comment-split, and entity-split heading aliases at their form
boundary instead of enumerating rendered spellings.

The critic attestation is canonical JSON between the markers and contains
`domain_results` in the exact coverage order. Every domain row is exactly
`{commands:[<single-line-allowlisted-command>],domain:<coverage-id>,evidence:["relative/file:line sha256:<64-hex-line-hash> <exact-trimmed-line-text>"],status:"clean"}`.
Every evidence path must resolve to a non-excluded file and an extant line in
the frozen corpus. Blank lines and the synthetic element after a terminal
newline are not evidence. Evidence has exact form
`relative/file:line sha256:<line-hash> <exact-trimmed-line-text>`; free-form
claim text is forbidden. It must be covered by one successful
`read-formation-evidence.mjs` slice whose reconstructed stdout carries that

run. A run begins with one child `functions.exec` call whose source is

outer `functions.exec` budget is fixed by the 60-second/50,000-token pragma;

120 polls, at most 3,900,000 milliseconds from its launch call to terminal

attestation command union; the union contains the allowlisted launch command

## Closure

The root writes `FORMATION-CLEAN-PASSES.json` only from the six persisted
session/report hashes. `tools/validate-clean-passes.mjs` proves actor rotation,
served route, exact report locations, report attestations, critic-to-adjudicator
hash joins, the pass-1-to-pass-2 predecessor join and the current corpus epoch.
Only then may `tools/validate-corpus.mjs` emit
`formationStatus:"complete"`.
