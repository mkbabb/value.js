# P–V Wave Registry

## Shared formation and execution law

Formation and implementation are two distinct stages. Before implementation,
the proposed wave contract is challenged by two fresh hostile Sol formation
critics and a third fresh Sol formation adjudicator under
[`../FORMATION.md`](../FORMATION.md). That formation triad may amend the
contract, but it reviews no implementation state and cannot satisfy the later
implementation challenge.

After formation accepts the contract, every implementation wave follows this
order:

<!-- VNEXT-IMPLEMENTATION-ORDER {"schema":"vnext-implementation-execution-order/1","steps":["born_red","partition","implement","freeze","critic_a_and_critic_b","adjudicator","acceptance_gate_and_downstream_crater","acceptance_receipt","return"]} -->

1. Capture its born-RED witness and input digests.
2. Partition the affected DAG cluster at a size justified by its actual edges.
3. Implement only the formation-adjudicated surface.
4. Freeze the exact final implementation state and evidence offered for acceptance.
   That state remains immutable through challenge, gate, receipt, and return.
5. Run the one compact fresh `critic_a`/`critic_b` plus adjudicator triad
   required by
   [`../RETURN-CONTRACT.md`](../RETURN-CONTRACT.md). The critics independently
   challenge that same immutable final state; the adjudicator starts only after
   both complete.
6. After ratification, run the one canonical acceptance gate and downstream crater
   named by the dependency boundary against that unchanged state. Its receipt
   starts after adjudication and seals the exact implementation-challenge hash.
7. Seal the outer acceptance return without mutating the reviewed and gated state,
   then return the complete packet below.

The accepted state has exactly one final-state triad, not a second proof gate
or a replay of formation critique. A finding reopens its exact owner; repair
invalidates that reviewed state and requires one wholly fresh triad for the new
state, followed by the applicable acceptance gate/crater, before acceptance.

A defect reopens its owning wave. Closure waves audit; they never repair.

## Shared proof and return law

[`../RETURN-CONTRACT.md`](../RETURN-CONTRACT.md) is the only normative return
schema. A band may add fields only below its namespaced `annexes` member and
may not redefine statuses or omit a universal field. P waves additionally
return typed `annexes.parser` with its exact scope class, the P00-validated
published 1.0.0 registry/no-link receipt projection, all four coordinate
domains, parser invocation and route counts, blocker dispositions, and the
byte-canonical external handoff digest. No candidate package branch exists.

Every row freezes `test/proof/<lowercase-wave-id>/manifest.json` before source
mutation and exposes the direct acceptance entrypoint
`node .vnext/proof-runner.mjs test/proof/<lowercase-wave-id>/run.mjs --manifest <path>`.
The manifest contains the exact born-RED projection, corpus and oracle digests,
fixed tolerances/budgets, at-limit and `+1` cases where bounded work is owned,
the downstream crater, and the expected receipt hash. A missing command,
missing fixture, skipped unsupported case, mutable threshold, workspace link,
or unhashed output is RED. Audit waves use a precommitted falsification suite;
they do not invent a synthetic implementation failure.
