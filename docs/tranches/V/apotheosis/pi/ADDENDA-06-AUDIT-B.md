| 6 | 6 | 5 | 10 | both schedules truncate a cycle |
| 16 | 16 | 5 | 10 | many subjects never occupy many positions |

For example, with `m=3`, a ten-block run gives one relabelled subject position
counts `[3,3,4]`, not a balanced Williams schedule. This is not a rejection of
Williams designs; it is a conflict between the design and the independently
fixed 5/10-block budgets.

## 2. Confirmed defects

### B2-01 — candidate-byte change is an unbounded optional-stopping escape

BR-2 permits a superseding attempt whenever emitted candidate bundle bytes
change. Only runtime/build/statistics changes and corpus/semantic amendments
explicitly need a pre-run causal hypothesis and review. The following sentence
says a "nominal digest change" buys no new draw, but `nominal` has no mechanical
definition and no gate binds event 1 to a reviewed causal source delta.

Consequently, after a valid loss an author can add reachable-neutral emitted
code or reorder equivalent emitted code, obtain a new candidate digest, a new
`qualificationId`, a new order seed, and a new bootstrap seed, and run again.
The prior loss remains in history but does not prevent draw-shopping. This
violates the sheet's own no-unchanged-loss objective even though the byte digest
did change.

**Required repair:** candidate-byte supersession must name a versioned,
content-addressed source delta and a pre-run causal hypothesis explaining why
it can change semantics, deterministic work, allocation, or timing. It needs
the same pre-measurement review class as events 2 and 3. A bundle-only or
semantically/performance-neutral emitted change remains the same attempt and
must not reseed order/bootstrap. Preserve the prior verdict and explicitly bind
old/new identities to the approved causal delta.

### B2-02 — environment identity and the no-retry law contradict each other

`qualificationId` binds a runtime schema described as Node/V8/OS/architecture
and flags. The stable machine ID, CPU identity, power state, and thermal receipt
are outside that identity. BR-2 also says a same-run comparison on a new
environment remains evidence, while BR-5 says a valid loss is never retried
under the same `qualificationId`.

Two machines with the same ABI/schema therefore produce the same
`qualificationId`. Either the second machine run is forbidden as a retry, which
contradicts the admitted new-environment evidence, or multiple potentially
different controlling verdicts share one qualification identity. An
environment receipt "binding" the machine after the fact does not provide an
identity or a deterministic rule for which result controls.

**Required repair:** introduce a canonical `environmentClassDigest` (excluding
timestamps but including the verdict-relevant stable machine/CPU/power fields)
into an attempt/run identity, and state exactly which level the one-valid-batch
rule governs. A portable schema-level `qualificationId` may remain, but then a
second content-addressed `qualificationRunId` must bind the environment class,
and the close matrix must define separate environment vectors rather than
pooling or competing same-ID verdicts.

### B2-03 — fixed 5/10 blocks do not implement the ratified "Williams-order" claim

BR-5 defines a full Williams cycle but BR-6 fixes five wave blocks and ten final
blocks regardless of `m`, while BR-5 accepts `2≤m≤16`. Except for incidental
combinations, those counts do not complete the cycle. The result is a
deterministic order, but not the claimed balanced order: subject positions and
first-order carryover are unequal. This matters because the candidate,
predecessors, and two anchors are deliberately executed sequentially and
process/machine drift is the reason for blocking in the first place.

The defect compounds B2-01: a nominal candidate bundle change changes the
relabel seed and therefore which subject receives the truncated-cycle
advantage.

**Required repair:** either make block counts an exact positive multiple of the
cycle length while retaining a predeclared minimum evidence count, or specify
and justify a different exact counterbalancing scheme that is balanced for
every supported `m` at the fixed counts. If the intended law is merely a
seeded incomplete schedule, stop calling it Williams-balanced, freeze that
limitation, and provide an analysis showing its order effect cannot control a
strict cell. The current owner choice says "Williams-order runner," so this
cannot be left implicit for the freeze packet to reinterpret.

### B2-04 — the aggregate point statistic is not defined

The sheet precisely defines per-subject sample medians, per-block
`speedRatio`, and bootstrap medians of `pairedLogSpeedRatio`, but the exhaustive
state table requires "median `speedRatio`" and anchor law uses a bare
`speedRatio`. With ten blocks there are two different written-compatible
aggregates:

1. arithmetic median of the ten ratios (arithmetic mean of the middle two), or
2. exponentiated median of the ten log ratios (geometric mean of the middle two).

They are not identical: middle ratios `0.90` and `1.11` give arithmetic median
`1.005` but exponentiated log median about `0.9995`. The sheet also asks to
report a "subject median ratio" without defining whether it is one of these or
a ratio of separately aggregated durations. Thus point classification and the
0.95 anchor threshold are not mechanically reproducible.

The final-only 9-of-10 sentence also leaves five-block wave cells unable to
satisfy the literal `FASTER` table row even if their confidence bound is above
one. That may be intentional because wave acceptance uses regression states,
but the sheet says *every qualification cell* has exactly one state and does
not supply a wave-specific `FASTER` definition.

**Required repair:** define one named aggregate, preferably
`aggregateLogSpeedRatio = median(pairedLogSpeedRatios)` and
`aggregateSpeedRatio = exp(aggregateLogSpeedRatio)`, and use it in every point,
anchor, report, and status clause. State explicitly whether five-block wave
cells use the same exhaustive states without the final sign clause or only the
separate GREEN/AMBER/RED regression disposition. No bare `speedRatio` may mean
both a block statistic and an aggregate.
