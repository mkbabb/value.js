## Blocking finding B1 — the emitted typecheck does not typecheck the verified overlay

`promotion-verifier.mjs` accepts any canonical caller-supplied overlay root,
but the emitted command is only:

```text
node <bound TypeScript bin/tsc>
  --project mirror/tsconfig.apotheosis.json --noEmit
```

That project includes `mirror/apotheosis/**/*.ts` and `mirror/cells/**/*.ts`.
It does not project the caller-supplied overlay into the active root, pass the
overlay file explicitly, generate a bound overlay config, or otherwise prove
that the exact file just hashed is in the compiler program. The verifier also
does not mechanically require `numberStart: Parser<boolean>`; it requires only
one directly exported variable with that name.

Concrete reproduction used an external canonical assay overlay containing only:

```ts
export const numberStart = 1;
```

The exact verifier exited 0 and emitted source, overlay, projected grammar,
parse-that, TypeScript, configuration, roots, and typecheck fields. The emitted
exact Node + bound `bin/tsc --project ... --noEmit` command then also exited 0,
because that overlay was not in the project. The verifier even permits this
root although `promotion-protocol.json` names the governed shape as
`cells/syntax-number-start/g6/candidates/<seat>/overlay`; it does not validate a
seat or that path ancestry.

This is not a demand that the AST floor prove semantics. It is a direct failure
of the claimed candidate-specific type gate and `internal_root` contract. A
future hidden harness would reject the non-parser at runtime, but hidden-corpus
failure cannot retroactively make the emitted promotion/typecheck identity
truthful. Bind a per-overlay compiler program/config (including the exact
verified file), require the exported root to be assignable to
`Parser<boolean>`, and either enforce the governed seat-root shape or explicitly
make arbitrary roots part of the protocol with equivalent isolation evidence.
