## Altitude 2 — feature-wave analysis

The feature contract and H2 agree on the complete operation:

1. an optional ASCII `+` or `-`;
2. either digits with an optional dot-followed-by-digits fraction, or a leading
   dot followed by digits;
3. an optional exponent only when `E|e`, optional sign, and at least one digit
   are all present;
4. maximal-prefix consumption;
5. `{ sign, type, value }`, with `type` changed to `number` exactly when a dot
   or complete exponent was consumed.

This is equivalent to the pinned CSS Syntax consume-a-number steps under the
contract's explicit starts-number precondition. Incomplete suffixes are not
over-consumed: `1.` and `1e+` both leave their incomplete suffixes after the
integer `1`; `.5E-2x` consumes through the complete exponent and leaves `x`.
Repeated fractions likewise terminate after the first valid representation.

## Altitude 3 — feature analysis

### Numeric value, sign, and type

`Number(representation)` is equivalent to the contract's JavaScript-number
projection and preserves the cases that matter here: `-0`, underflow to signed
zero, overflow to signed infinity, and ordinary binary64 rounding. The sign is
derived independently from the first consumed code unit, so `-0e-999` returns
`sign: "-"`, `type: "number"`, and numeric negative zero. ASCII-only `[0-9]`
matches CSS Syntax's digit production and does not admit Unicode lookalikes.

### Transaction and parent composition

On failure, the parse-that regex/map pair returns the same state object, marks
it erroneous, and retains source identity, offset, predecessor-value identity,
and diagnostics whose furthest observation is already ahead. The map does not
run on failure. On success, the source is unchanged and only the UTF-16 offset
advances.

Independent direct probes confirmed:

- `1.2%` composes with a percentage parent;
- `1e2px` composes with a dimension parent after a complete exponent;
- `1e` correctly composes as integer `1` plus unit `e`, because the apparent
  exponent is incomplete;
- `1e+` is rejected by that complete dimension parent because `+` remains;
- `.5/` composes with a delimiter parent.

This behavior is precisely why H2 must remain a maximal-prefix leaf rather
than add `.eof()` or unit/delimiter policy locally.

### Result object

Every successful call creates a fresh ordinary object with own keys in exact
order `sign`, `type`, `value`. Each is an enumerable, writable, configurable
data property; the object has `Object.prototype`, remains extensible and
unfrozen, and can be mutated without affecting later results. The parser ID,
context identity, own keys, and printable representation remain stable across
calls, and the allocation sentinel reproduced no per-invocation Parser growth.

### UTF-16 and hostile inputs

The candidate consumes from the supplied parse-that UTF-16 offset rather than
retokenizing or slicing a private source. A direct probe of `😀-.0E+9%` from
offset 2 ended at offset 8 and returned signed negative zero; wrapped and lone-
surrogate cases in the replay also matched the independent oracle. Invalid
starts such as `.`, `+`, and `e1` failed transactionally. The bounded hostile
suite includes long sign, dot, exponent-marker, digit, repeated-fraction, and
astral strings and reproduced no throw or state corruption.
