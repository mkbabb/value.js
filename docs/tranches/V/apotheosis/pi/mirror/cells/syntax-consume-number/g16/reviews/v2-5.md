## Altitude 1 — total-tranche gestalt

`consume-number` is an appropriate first atomic boundary. It is a normative CSS
Syntax algorithm, has high fan-out into percentage, dimension, calc/math,
color, transform, media, property, and keyframe productions, and can be closed
without inventing any parent delimiter or complete-input policy. Accepting this
leaf removes a common dependency without prematurely deciding those parents.

The placement `grammar/css/l4/value-unit/numeric` is coherent with the bound
BBNF family and does not create another lexer. The implementation is a direct
parse-that terminal and projection; it emits the semantic result of one
production, not a token tape, atom, component-value object, CST, cursor API, or
scanner service. BBNF isomorphism here is ownership and dependency isomorphism,
not a requirement to expand a regular terminal into ceremonial combinator
nodes.

This boundary should not become a precedent for running the full formation
process around every punctuation terminal. It is justified because it is a
normative, semantic, shared operation and the first dependency of the runnable
value-unit-to-keyframes vertical. Once synthesized, the tranche should proceed
directly to percentage/dimension and keyframes composition instead of creating
another admission-protocol generation.

## Altitude 2 — feature and downstream composition

The feature owns exactly the intrinsic consume-number facts:

- optional `+`/`-` sign;
- the integer, fractional, leading-fraction, and complete-exponent forms;
- maximal-prefix behavior for incomplete fraction/exponent continuations;
- integer-versus-number classification; and
- base-10 conversion into the required mutable `{sign,type,value}` leaf.

It correctly does **not** own `%`, dimension units, integer-only constraints,
range bounds, whitespace, delimiters, EOF, or error-policy decisions. A
percentage parent can sequence this parser with `%`; a dimension parent can
sequence it with the separately governed identifier/unit production; a
keyframe percentage parent can apply its own bounded or unbounded numeric
domain. The 24 parent-composition cases and transactional checks support this
use rather than merely proving complete-input examples.

The private `CssNumber` alias is not an integration blocker. The frozen feature
requires the runtime `consumeNumber` export, and TypeScript infers its exact
`Parser<CssNumber>` output. A later type-only barrel may name the structural
shape without changing this accepted parser. No representation string or token
object is required by the bound consume-number algorithm; source-preserving or
token-level concerns remain parent/result-boundary work.

## Altitude 3 — code, selection, and performance scope

H2 is the KISS winner among the bound candidates:

- H2 and H are the minimum 17 lines, but H2 uses the digit-first equivalent
  mantissa ordering that earned the valid confirmatory result.
- B is a readable algorithmic decomposition, but requires 64 lines, many
  intermediate parsers and values, and a redundant starts-number lookahead for
  a regular leaf.
- S expands the same small language to 81 lines and staged empty-string
  decisions.
- D is compact but duplicates the complete number language across three regex
  branches and introduces dispatch machinery without a semantic ownership gain.

H2 uses one module-initialized `regex` parser and one adjacent `.map`. `[0-9]`
keeps CSS digits ASCII-specific; the alternatives expose the two mantissa
shapes; the exponent is all-or-nothing; and the projection keeps sign, type,
value, and property order visible. There is no hidden source loop, slice,
runtime state, speculative abstraction, or per-call parser allocation.

The benchmark proves only the declared normalized leaf endpoint on one pinned
64-row common-domain corpus and environment. It does not prove per-case
dominance, production-distribution speed, full value-unit speed, full-parser
throughput, or wins over every alternative candidate. That narrow claim is
enough for this selection because correctness and direct architectural
comparison independently select H2, while the benchmark establishes the
required strict win over the exact deposed operation-equivalent peer. Broader
performance remains an integration obligation and receives no credit here.
