## 1. Total-tranche analysis

H2 is the appropriate kind of foundation leaf for the reset tranche. It is a
direct production in the `value-unit/numeric` owner, and percentage, dimension,
integer-only, delimiter, and complete-input policy remain in composing grammar
productions. Its source does not introduce a competing lexical architecture or
make CSS-number interpretation depend on a token object.

The candidate uses one published parse-that `regex` terminal and one `map`.
There is no source/cursor loop, substring scanner, remainder capture, token
tape, atom, component-value object, CST, mutable cache, process access, or
filesystem access. Although the published `core` module exports unrelated
balanced-splitting utilities, the candidate neither imports nor invokes them;
their mere presence in the package export module is not a grammar seam.

This leaf alone proves no broader CSS-L4 completeness, public diagnostic
fidelity, serialization, or integrated parser performance. The subject states
zero such credit, so its narrow scope does not misrepresent tranche progress.

## 2. Wave analysis

The exact published 1.0.0 implementation behind the bound tree was inspected
through its bound source map. `regex(r)` removes a supplied sticky flag, creates
one sticky `RegExp` when the parser is constructed, sets `lastIndex` to the live
UTF-16 offset, and accepts only a nonempty match beginning there. Its default
path returns the exact matched substring and end offset. `map` invokes the H2
projection only after success and otherwise returns the failed state unchanged.

That interaction establishes the relevant state laws:

- construction happens once at module evaluation: one regex Parser and one map
  Parser; a call constructs neither;
- the shared sticky regex cannot leak a prior offset because every call assigns
  `lastIndex` before testing;
- on failure, the regex/map pair changes neither offset nor predecessor value;
- a pre-existing diagnostic whose `furthest` position is ahead is not replaced;
- parent combinators can roll the leaf back on a later delimiter failure;
- success offsets are ECMAScript UTF-16 code-unit offsets, matching the frozen
  contract.

I reran the bound correctness replay, without timing or writes. It reproduced
180/180 holdout cases, the frozen public rail, and 65,024 independent scanner-
oracle transactions. Covered families include maximal prefixes, incomplete
fractions and exponents, nonzero/UTF-16 offsets, predecessor and ahead-diagnostic
transactions, parent composition, mutable descriptors, repeated calls,
introspection, hostile strings, and Parser-ID stability.

I then ran a separate read-only, no-timing runtime probe over eight targeted
edge cases, a one-million-digit representation followed by a sentinel, 10,000
repeated calls, and a parent-delimiter rollback. It reproduced exact maximal
prefixes for `1.e+2`, `+.5E-2x`, `1.2.3`, `1e+`, a surrogate-offset case, and
the expected failures for `.` and `+`; the million-digit input advanced exactly
one million UTF-16 units and projected `Infinity`; Parser ID/context remained
stable; and the failed parent restored offset zero.

## 3. Feature analysis

The terminal

`[+-]?(?:[0-9]+(?:\.[0-9]+)?|\.[0-9]+)(?:[Ee][+-]?[0-9]+)?`

implements the required regular language and its maximal-prefix behavior:

- optional `+`/`-` is consumed only as part of a complete mantissa;
- an integer may have a fractional part only when the dot has a following
  digit;
- a leading dot requires at least one digit;
- an exponent is consumed only when its optional sign is followed by a digit;
- incomplete dot/exponent and repeated-fraction suffixes remain for the parent.

The alternation ordering does not shorten digit-led fractions: the optional
fraction is greedy before the integer arm can finish, and the outer exponent is
then greedily considered. Native sticky matching is linear for this bounded
shape; the source contains no nested unbounded ambiguity or backreference.

The projection preserves the consumed spelling's sign, classifies as `number`
exactly when the consumed spelling contains a dot or exponent marker, and uses
`Number(representation)` as required, including signed zero, underflow, and
infinity. The object literal gives an ordinary extensible object with exactly
the enumerable/writable/configurable `sign`, `type`, `value` key order and a
fresh identity per call.

No blocking defect was reproduced. The package loader's top-level DEP0205
warning is external to H2 semantics and was not mistaken for a candidate
failure; no benchmark timing was performed in this review.
