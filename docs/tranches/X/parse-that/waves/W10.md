## Owner rulings this wave needs (proposed arms; a unit whose ruling is open does not start)
- **DR-a, property-aware grammars (XP-10 (a); W8g-PROPERTY-GRAMMAR 866, W8v-PROPERTY-GRAMMAR 5).** *Recommend: keep.* `parseCssValue` stays property-agnostic by design, and the 871 rulings stand. A `parseCssProperty(name, value)` with per-property BBNF is a separate tranche-sized claim, not W10.
- **DR-b, canonical specified-value serialization (XP-10 (b); about 2,557 serialization rows).** *Recommend: keep.* value.js is a colour library, and its colour canonical form (named → `rgb()`, its calc order) is product policy. The rulings stand. W10 cures only serialization that a W10 unit's own grammar produces.
- **DR-c / XP-14, absolute-origin relative colour.** *Recommend: resolve at parse.* The origin is absolute when it is a named colour, hex, or a colour function with absolute channels. It is not absolute when it is `currentcolor`, a system colour, `var()`, `light-dark()`, or a context-dependent nested origin. An absolute origin is resolved in `parseCssColor`, with channel keywords bound and channel math resolved (the SC-1 `calc()`-in-channels precedent). A context-dependent origin keeps `color_context_required` (R-c-2 stands). `parseCssValue` keeps the specified form for WPT `test_valid_value`.
