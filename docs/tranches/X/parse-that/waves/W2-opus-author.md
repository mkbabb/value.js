### 3b. The algebra — the normative object (what phase 1 and 2 produce)

The algebra is **not** a combinator library and **not** a grammar DSL. It is a closed set of typed
operators over a four-part state, with laws that both lowerings must satisfy observably.

**State.** A parse of input `S` is a function to `(V, C, P, D)`:

| part | what it is | why it is separate |
|---|---|---|
| **V** — semantic value | exactly the frozen `/css` value types (`CssColor`, `CssTimingFunction`, `Stylesheet`, …) with **zero** extra properties | this is the no-CST claim made checkable: `V` is assignable to the frozen type under an excess-property check |
| **C** — byte complement | an ordered list of `(offset, length, kind)` for every byte of `S` **not** injected into `V` — whitespace, comments, case spelling, separator choice, skipped malformed spans | the CST is exactly `(V, C)` fused into one tree; splitting them is what lets `V` be a plain value |
| **P** — provenance | a side table from `V`'s construction-ordered leaf index to `(start, end)` in `S` | provenance without tree position; an array, not a node field |
| **D** — diagnostic journal | an append-only ordered list of `ParseIssue` values | `ParseIssue` is already frozen: 8 codes, `start`, `end`, `expected[]`, `actual` (`src/css/types.ts:10-24`) |

**Law COMP-1 (conservation / the malformed inverse).** For **every** `S` in the closed set —
accepted *or* malformed — `weave(V, C, P) === S`, byte for byte. This single law subsumes the
handoff's "byte complement" and "malformed inverse" clauses, and it is the reason recovery cannot be
an escape hatch: bytes skipped by recovery must land in `C` or the law breaks.

**The operator set (closed; this arm's proposal, subject to agglomeration).** Sixteen operators in
four families. The count is normative — the point of a *finite* algebra is that the enumeration is
the thing.

- **Leaves (5)**: `lit(bytes)` · `scan(set)` (advance while/until a byte-class membership test) ·
  `span(kind)` (consume into `C`, never into `V`) · `succeed(v)` · `fail(expected[])`.
- **Structure (5)**: `seq(...)` · `alt(...)` (ordered, committed on first byte-level discriminant) ·
  `rep(p, min, max)` · `opt(p)` · `bind(p, f)` (value-dependent continuation).
- **Semantics (3)**: `emit(f)` (construct a `V` leaf and append to `P`) · `clamp(range)` ·
  `scale(num, den)` (**written as `(value * num) / den`, never as a folded factor** — parser-band's
  exactness note: `n * 0.01 !== n / 100` for 114 of the 1001 values `0, 0.1, …, 100`, and that is
  exactly why the two spellings of `hsl()` must not drift).
- **Recovery (3)**: `mark()` · `rollback(mark)` · `recover(p, sync, sentinel)` — see §3f.

**O-8 (the anti-latch clause).** No operator reads or writes process-global mutable state. Arming,
memoization, and diagnostics are **parameters of a parse**, never latches. This is O-15 PT-03 turned
into a construction rule: a one-way `PACKRAT_ARMED` that costs `1.47×` and cannot be disarmed
(`resetPackrat()` measured at `139.3` ns, still armed) is not a performance knob — it is a state
machine with one absorbing state, and no algebra with a global absorbing state can satisfy EQ-1
across two lowerings that arm at different times.

**The six equality clauses (EQ-1..EQ-6)** — the dual-target contract, one oracle cell each:

| id | clause | comparison | "exact" means |
|---|---|---|---|
| EQ-1 | semantic value | structural deep-equal of `V` | **bit-for-bit f64** on every numeric channel (`Object.is`, so `-0` and `NaN` are distinguished), not `===` epsilon |
| EQ-2 | byte complement | ordered list equality of `C` | same order, same `(offset, length, kind)`; `weave` round-trips both |
| EQ-3 | provenance | ordered `(start,end)` array equality of `P` | leaf construction order must match, which forces the two lowerings to build `V` in the same order |
| EQ-4 | diagnostics | ordered structural equality of `D` | `code`/`start`/`end`/`expected[]`/`actual` — **not** rendered strings (OP-4) |
| EQ-5 | rollback | post-failure state equality | offset, journal length, and complement length restored to the pre-`mark` values; **cost asymmetry is declared, not equalized** (§3f) |
| EQ-6 | malformed inverse | COMP-1 on the malformed corpus | `weave(V, C, P) === S` for inputs that produce `ok:false` |

**A contract detail that is load-bearing and easy to miss**: `ParseResult`'s failure arm is
`{ ok: false; diagnostics: readonly [ParseIssue, ...ParseIssue[]] }` (`src/css/types.ts:27`) — a
**non-empty** tuple. The frozen contract already forbids a silent failure. That kills O-15 PT-07's
shape (`.parse()` returning `undefined` on failure, indistinguishable from a successful `undefined`)
at the type level, and it makes "every rejection carries at least one diagnostic" a *contract*
obligation rather than a nicety.

### 3c. The five architecture candidates (novel research, M-25 ¶2b)

Each is a distinct answer to *"how does one algebra become two artifacts?"* Each carries a
**predicted failure mode** and a **pre-declared falsifier**, written before measurement.

---

**A-1 — TWIN-EMITTER.** *One IR, two backends.* The algebra is a serialized data structure (the
sixteen operators as a typed tree). Two emitters at build time: one emits TypeScript that calls
parse-that's combinator surface; one emits Rust compiled to `wasm32-unknown-unknown`. The IR file is
the single normative artifact; neither emitted source is edited by hand.

- *Predicted failure 1 — **backend-conditional escape hatches**.* The IR grows `if wasm: use
  scan_digits_simd` nodes and stops being one algebra. This is the handoff §5 defect wearing a new
  coat: a declared set (16 operators) drifting out of bijection with its lowering table (18 vs 20).
- *Predicted failure 2 — **toolchain capture**.* Reproducing the JS artifact requires nightly Rust
  (`rust-toolchain.toml:39` pins `nightly-2026-04-11`; `lib.rs:1` is `#![feature(portable_simd)]`).
  A value.js consumer build that needs a nightly Rust toolchain is dead on arrival regardless of speed.
- *Falsifier*: **any** IR node whose lowering is not total in both backends → killed. **Or**: the
  emitted-JS build step transitively requires `cargo` → killed.

---

**A-2 — WASM-PRIMARY, JS DERIVED.** Write the algebra once in Rust; ship Wasm for one target and
derive the JS target from the same Rust (mechanical translation, `wasm2js`-class, or a generated
monolithic JS module).

- *Predicted failure — **it re-creates the thing the pause killed**.* Any mechanical Rust→JS lowering
  produces a typed-array interpreter with hand-rolled cursors: unreadable, un-idiomatic, and
  precisely the "generated source" posture the v12 construction died in (handoff §3.2: generated
  source SHA `26757d48…`, **1,965,705 bytes**, writes 0, target ABSENT). It also fails the prompt's
  own constraint that the JS lowering be *the library's own combinator surface*.
- *Falsifier*: the derived JS artifact fails the idiom gate (G-6) on any of — hand-rolled cursors,
  `.parse(` truthiness entry, `as any`, `!` non-null assertion, zero use of the combinator surface.
  Screened at Stage 0 because this falsifier is decidable from a **50-line** spike, not a full port.

---

**A-3 — ALGEBRA-AS-LIBRARY, WASM AS A LEAF.** Do not compile at all. Grow parse-that's combinator
surface with the scan/lex primitives it lacks (`scan(set)`, `spanUntil`, `wsComment`, `digits`,
`quoted`, `balanced`) so the CSS grammar is written **once**, idiomatically, in TypeScript; reach the
Wasm target by making those **leaves** wasm-backed over a shared `Uint8Array`.

- *Why it is credible*: the Rust crate already owns the whole scan cluster —
  `rust/parse_that/src/scanners.rs` (`find_first_of` dispatching memchr for 1–3 targets, a nibble-LUT
  SIMD kernel for 4–8, a 256-byte scalar LUT for 9+) plus **13 files** in
  `rust/parse_that/src/parsers/scan/`, and those 13 **are committed**
  (`git ls-tree --name-only HEAD …/scan/ | wc -l` → `13`). The TypeScript side has **zero**:
  `grep -rl 'simd\|SIMD' typescript/src` → **0 files**; `find typescript/src -name '*scan*'` → **0**.
  The union the prompt asks for — SIMD-scan/lex *inside* the combinator library — exists on exactly
  one side today, and that asymmetry is the finding, not an accident.
- *Credibility discount, stated honestly (OP-5)*: the **wasm32** half of that cluster is **not
  committed**. `git grep -c "wasm32" HEAD -- rust/parse_that/` returns nothing; the target gate and
  every `core::arch::wasm32` kernel live only in the evidence root's working tree. A clone at
  `f5757082` gets the scalar/aarch64 scan cluster and **no Wasm kernels at all**. A-3's leaf-wasm
  story therefore begins one step further back than the tree first appears to promise.
- *Predicted failure — **the boundary eats the win**.* A leaf-level JS→Wasm call costs on the order
  of tens of nanoseconds against a **93.9 ns** whole-parse budget (O-15 PT-03, unarmed). One boundary
  crossing per token can exceed the entire parse.
- *Predicted failure 2 — **it answers a weaker question**.* "Zero-function-import Wasm" is satisfied
  trivially (the module imports nothing; JS calls *in*), but the hypothesis wanted the parse **in**
  Wasm. A-3 may win on numbers while not testing the conjecture.
- *Falsifier*: measured mean boundary cost per leaf call ≥ **20%** of the whole-parse budget on the
  vertical slice → killed. (The 20% is a *screen threshold internal to this wave's candidate
  selection*, not a performance bar; G-10's bar remains owner-gated.)

---

**A-4 — TWO SIBLINGS, ONE ORACLE.** No compiler. Two hand-written implementations — cand-O's
four-file TypeScript architecture (`ast.ts` 112 · `spec.ts` 223 · `grammar.ts` 480 · `index.ts` 200 ·
`named-colors.ts` 194 = **1,209 lines**, measured) and a Rust sibling — both consuming the **same**
machine-readable channel table. The algebra is normative as *specification + differential oracle*
rather than as generated code.

- *Why it is credible*: parser-band already measured two independent hand-written grammars agreeing
  on **30,000 seeded fuzz inputs with zero acceptance disagreements**, and cand-O's `spec.ts` is
  already a table ("the ONE place a range lives"; `rgb()` and `oklch()` are rows). Extracting that
  table to JSON makes it consumable by a Rust sibling with no compiler in between.
- *Predicted failure — **drift with nothing to stop it**.* Two hand-written parsers that agree on
  30,000 inputs diverge on input 30,001, and the only thing standing between the lane and a silent
  divergence is oracle coverage — which is exactly what §3e's closed set is for. This is not a
  hypothetical: the seven measured cand-F/cand-O disagreements (hue wrap ×2, `xyz-d50` adaptation,
  token juxtaposition ×3, `1e400`) were all found by an oracle, none by review.
- *Predicted failure 2 — **maintenance doubles**.* Every css-color-5 addition is two edits. That is
  the exact axis on which cand-O beat cand-F ("a table row vs a new function") — A-4 re-imports the
  cost it was chosen to avoid, one level up.
- *Falsifier*: any semantic divergence the oracle cannot classify as a **declared** divergence row →
  killed. A divergence discovered after the wave's fuzz budget is spent is *also* a kill, recorded
  with the seed.

---

**A-5 — TABLE-DRIVEN SEMANTIC MACHINE.** The algebra compiles to a compact byte-coded program
(`SCAN_SET`, `EXPECT`, `PUSH_CHANNEL`, `SCALE`, `CLAMP`, `EMIT`, `MARK`, `ROLLBACK`, `RECOVER`, …).
The JS lowering is a small interpreter over a `Uint8Array` program; the Wasm lowering is the same
interpreter in Rust. **One program, byte-identical in both**; two interpreters.

- *Why it is credible*: EQ-1..EQ-6 become nearly free — the same program cannot disagree with itself,
  so the only divergence surface is the two interpreters' arithmetic, which is a **far** smaller

### 3f. Error recovery as a first-class algebra citizen

Recovery is not a wrapper around a failure. It is three operators with four laws, and it is the only
reason `C` (the byte complement) has to exist.

- **R-LAW-1 — rollback exactness.** On `p` failing inside `recover(p, sync, sentinel)`, the state
  restored before the skip begins is exactly the pre-`mark` state: offset, journal length, complement
  length, and (Wasm) arena watermark. *Falsifiable*: a probe whose `p` appends to `D` and `C` and
  mutates a channel accumulator, asserting all three restored.
  **The lowerings differ in cost, not in value, and the algebra must say so**: the Wasm side gets
  rollback for free by truncating a bump arena (`rust/parse_that/src/bump_slab.rs` — "no Drop",
  single-threaded, trivially destructible allocations); the JS side has no watermark, so its failing
  path must be provably **allocation-free** or the two rollbacks are observably different in GC
  pressure while identical in value. EQ-5 tests the value; G-8 measures the cost; the algebra
  **declares** that value is normative and cost is reported.
- **R-LAW-2 — complement conservation.** Bytes skipped by recovery enter `C`; they never vanish.
  COMP-1 must hold on malformed input. *Falsifiable*: any malformed fixture whose `weave` output
  differs from `S` by one byte.
- **R-LAW-3 — diagnostic purity.** A diagnostic is a value appended to `D`. Never an effect.
  This is O-15 PT-01 made law: in the substrate today, `label` is a no-op unless diagnostics are
  armed, and arming couples an unconditional `console.error` (`dist/diagnostics-*.js:14` +
  `dist/packrat-entry-*.js:881`) — the two are reachable only together. An algebra whose diagnostics
  can print cannot satisfy EQ-4 across two lowerings, because one of them has no console.
  *Falsifiable*: run the full corpus with `console.error`/`console.warn` monkey-patched to throw.
- **R-LAW-4 — non-amplification and progress.** Recovering from `N` malformed sites yields exactly
  `N` diagnostics, and `sync` must consume ≥1 byte or the recovery does not re-enter. A recovery that
  matches at the current offset and re-enters is the classic infinite loop.
  *Falsifiable*: a fixture where `sync` matches at offset 0 of the failure — the parse must terminate
  with exactly one diagnostic, not hang and not emit `N²`.
- **R-LAW-5 (the `alt`/`recover` interaction — named because it is a trap).** A recovered branch is a
  **success** for the enclosing `alt`, so an `alt` whose first arm recovers never tries the second.
  The algebra must state this explicitly and forbid `recover` inside a non-final `alt` arm, or state
  the alternative rule. Leaving it undeclared is how a "lenient" parser silently stops being total.

**Inherited debts folded here** (parser-band, binding on the wave): **labelled failures** — the
`fail(expected[])` leaf carries cand-F's named expectations (`"<named-color>"`,
`"<hex-color> (3, 4, 6 or 8 digits)"`) rather than cand-O's opaque `(?!)`; **recursion bounded by
construction** — the depth bound is an algebra parameter (O-15 PT-04 measured the substrate's
ceiling at **7,761**, `RangeError` at 7,762), so exceeding it becomes an ordinary `ok:false` with a
diagnostic, and any try/catch shield must be proven non-load-bearing; **the reject-path budget** is
its own bench leg, because a rejection that allocates is a rejection that lies about its cost.
