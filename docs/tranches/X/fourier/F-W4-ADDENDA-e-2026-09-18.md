## A-e-4 · `G-F4-PRM-CLOCK`: the reduced arm was telling the reader they had read nothing

The gate: *"every JS clock consults `prefers-reduced-motion`; the reduced arm renders a
**converged/static-truthful** frame, never a blank one"*, with the standing rider ⊘ *"gating
`playing` at mount freezes at t=0 — the reduced arm seeds the TERMINAL frame."*

**No row in the wave's `/paper` set names the reading-progress bar.** The gate found it, which is
what a gate is for, and this is recorded as a finding rather than folded into a row that did not
predict it.

**The producer half, read at the installed bytes** (`web/node_modules/@mkbabb/glass-ui/dist/styles/scroll-driven.css`,
the whole recipe, unedited):

```css
.scroll-progress{transform-origin: 0 50%;transform: scaleX(0);}
@media (prefers-reduced-motion: no-preference){@supports (animation-timeline: scroll()){
  @keyframes gl-scroll-grow{from{transform: scaleX(0);}to{transform: scaleX(1);}}
  .scroll-progress{animation: gl-scroll-grow auto linear;
    animation-timeline: var(--scroll-progress-timeline,scroll(nearest block));}}}
```

The keyframe **and** the timeline both sit inside `@media (prefers-reduced-motion: no-preference)`,
over a base rule of `transform: scaleX(0)`. So under PRM the composited path is inert on every
engine, not merely on engines without `scroll()` timelines.

**The consumer half** disarmed its JS floor under PRM as well —
`if (NATIVE_SCROLL_TIMELINE || prm) return;` — on the reasoning, written in the comment, that *"the
native recipe is inert and a JS bar would defeat PRM"*. Both paths silent means a 2px bar pinned at
zero for the entire read.

**The born-RED witness, measured rather than argued.** In a `reducedMotion: "reduce"` context,
scrolled to `1.000` of the paper, reading the bar's computed transform with the writer's inline
value dropped so that only the cascade paints — which is precisely the frame the prior arming
condition left behind:

```
[prefers-reduced-motion: reduce] scrolled to 1.000
   with the JS writer: matrix(1, 0, 0, 1, 0, 0)
   cascade alone (= the prior arm): matrix(0, 0, 0, 1, 0, 0)
[prefers-reduced-motion: no-preference] scrolled to 1.000
   with the JS writer: matrix(1, 0, 0, 1, 0, 0)
   cascade alone (= the prior arm): matrix(1, 0, 0, 1, 0, 0)
```

The no-preference arm is the control: there the cascade alone already converges, so the writer
correctly stays off and the dual-path-single-writer discipline is intact. **The reduce arm is the
gate's blank frame, and it is worse than motion, because it is false.**

**The cure** (`d0a87da`) is one operator: `if (NATIVE_SCROLL_TIMELINE && !prm) return;` — *absent OR
inert*. What is armed is not a clock: it owns no timer, the bar carries no transition and no easing,
and one `requestAnimationFrame` coalesces a scroll burst into a single write of the position the
reader themselves produced. PRM asks for no gratuitous motion; it does not ask to be misinformed.
Both arms now read `matrix(1, …)` at the end of the paper, double-run.

**A dead declaration found in the same read.** The consumer set
`--scroll-progress-scroller: nearest` and commented that it *"binds the native `scroll()` timeline
to the paper scroller (not root)"*. The recipe reads `var(--scroll-progress-timeline, scroll(nearest
block))` — **a different custom property**. The declaration bound nothing; the bar tracked the right
scrollport because that is already the default. Behaviour right by accident, comment claiming right
by construction. Deleted rather than renamed: the default *is* the intent, and a declaration that
restates a default is the next dead one.

## A-e-6 · `PSM-28` survived its own first cure, and the rider written for it found the remainder

`PSM-28` is *code points, not code units*: `fuzzyMatch` walks UTF-16 code units while the highlight
renderer splits with `[...text]`, so match indices land one place left of what the reader sees. The
first cure built a code-unit → code-point map over the **original** text.

**That is one of two length axes, and the smaller one.** `String.prototype.toLowerCase()` may return
**more code points than it was given**: `"İ".toLowerCase()` is `"i"` + U+0307, two for one. The
match runs over the lower-cased text; the map was built over the original; every index after the
first such character was shifted. Written as an assertion and executed:

```
FAIL  highlightFuzzy("İstanbul set", "set")   marked "tt"   expected "set"
```

— which is the defect the row describes, still live, after the cure named for it.

**The cure that closes both axes with one map**: build the lower-cased text one code point at a
time, and have every code unit it emits record the index of the **original** code point that
produced it. The matcher then indexes what it indexes and the renderer marks what the reader sees.
⊘ Lower-casing per code point gives up the handful of context-sensitive foldings (Greek final
sigma); that is the right trade for a highlighter, because a mark in the wrong place is visible to
every reader and a σ/ς near-miss costs a highlight on a query nobody has typed. The trade is written
at the site, not left to be rediscovered.

**This is the argument for `G-F4-VITEST` in one row.** Neither failure is visible on a rendered page
unless the reader happens to search a label containing `𝔽` or `İ`. The gate's value here was not
regression cover; it was **finding the defect at all**.

The unit floor this seat landed, at `.g`'s ruled runner home:

- `web/e2e/unit/paper-figure.vitest.ts` — 5 assertions over `resolveFigure` (`PAW-24`'s dead `.pdf`
  replace · variant emission only for known figures · intrinsic dimensions · variant/dimension-table
  agreement · `DARK_INVERT_EXEMPT` membership inside the known figure set).
- `web/e2e/unit/paper-search-scoring.vitest.ts` — 9 assertions over `PSM-14`'s length penalty and
  `PSM-28`'s code points.

⊘ **The import lock is honoured in both files**: `fuzzyMatch` and `highlightFuzzy` are imported from
their **definitions**, never from `search/index.ts`. A test that imports the barrel manufactures the
consumer whose absence is `G-F4-DEAD-DEP`'s proof.
