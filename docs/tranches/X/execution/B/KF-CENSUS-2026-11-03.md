## Dispositions

### R-1 · `control-label`: a stale selector (re-derived, tuple unchanged)

- **Reading:** `.labeled-field-label` matched zero elements on all 7 scenes.
- **Canon:** glass-ui 10.1.3 `LabeledField` no longer renders a `.labeled-field-label`. It seats its published `Label` (`data-slot="label"`, glass `.label{font-family:var(--font-text);font-weight:500}`) inside `.labeled-field-copy`.
- **Re-derivation:** the selector is now `.labeled-field-copy > [data-slot='label']`, and the expected tuple stays `{voice: body, weight: 500}`. It matches 33 labels, all reading Jakarta 500.
- **Dead code:** the demo's `style.css` override `.labeled-field-label{font-family:var(--font-text);font-weight:500}` targeted a class that is no longer rendered, and its stated reason ("glass binds the display face") is false at 10.1.3. It is deleted.
- **Not a loosening:** the row now checks 33 real labels against the same tuple. Before, it checked nothing.

### R-2 · the canon's three tabular readout cells (14 leaves; re-derived)

- **Reading:** each leaf is Fira Code with `font-variant-numeric: tabular-nums`, and none carries the `tabular-nums` utility class. The register's clause (b) only recognised that class: `[class*='tabular-nums']`.
- **Canon:** each of these leaves is a demo idiom whose own rule sets the mono data voice on itself:
  - `.param-row > .param-value`: design-idioms.css §PARAM-row (X.KF.W13V.y, OA-51 / DESIGN-NOTE N-2): "the value seats on the label's line … in the mono-as-data register (§1)".
  - `.stage-readout > :last-child`: design-idioms.css (KF-C7-07, KF-C9-06): "a sans label … the value is the scene's live state", set as `font-family: var(--font-mono); font-variant-numeric: tabular-nums`.
  - `.weight-readout`: LayerConfigPanel.vue (UIA-KF-081): "a fixed width of tabular numerals".
- **Why the register missed them:** the census used to visit `#/undefined`, so it never saw these scenes.
- **Re-derivation:** `monoAllowedSelectors` now names these three selectors exactly, and `_monoContract` (b) cites each one. Each must match the leaf itself. No `… *` descent entry was added, so clause 3's rule against admitting a leaf through an ancestor is unchanged.

### C-1 · spring preset tiles (12 leaves; kf defect, cured at root)

- **Defect:** the `tabular-nums` and `text-mono-small` classes sat on the `.preset-values` run. The two value `<span>`s and the `<span class="preset-sep"> · </span>` were bare mono leaves, which is exactly the admission through an ancestor that clause 3 refuses.
- **Cure (SpringPhysicsFacet.vue):**

  - The fit (`min(--type-small, 100cqi / 9.5)`, nowrap) and the stacking are unchanged.
